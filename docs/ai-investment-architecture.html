AI BUY-SIDE OPERATING SYSTEM

A 股主动多头中线多 Agent 投研系统

这不是一个泛化的研究助手，而是一套围绕真实买方流程搭建的工作系统： 以固定 workflow 为骨架，以专职 agent 为节点，以行业知识库和 thesis 记忆为长期资产，以人工审批为最后闸门。

固定流程骨架 按买方岗位拆 agent 长期记忆可累积 人保留最终决策权
市场 A 股
策略 主动多头
持有周期 中线持股
当前边界 生成操作建议，不自动下单

整体理解

系统的核心目标

今天该不该动仓

每天盘前围绕市场环境、持仓状态、候选替代和风险约束形成统一动作框架。

动哪个仓、怎么调

不是只判断单票对错，而是从组合角度回答钱从哪里出来，去哪里更划算。

哪些仓位继续拿

把 thesis 状态、催化剂、估值与风险结合起来，避免无效交易和叙事漂移。

哪些风险要优先处理

让 Bear Case 与 Risk Officer 成为常驻刹车系统，而不是事后复盘角色。

六层架构

从决策目标到底层治理的完整分层

L1

投资决策层

定义系统每天到底要回答什么问题。

今天该不该动仓 动哪个仓 仓位怎么调 哪些持仓继续拿 哪些候选值得进入组合 哪些风险需要优先处理
L2

工作流层

系统主骨架，节点顺序固定，agent 在节点内履职。

P0 第一阶段必须上线
  • 每日持仓决策流：07:45 主触发，08:55 条件重跑，输出《今日持仓操作单》
  • 盘后状态更新流：15:30 更新持仓状态、执行结果、thesis 状态
  • 持仓事件应急流：重大公告、暴雷、政策突变、异常波动时快速重评
P1 第二阶段建议上线
  • 新机会发现流：定时补充候选池
  • 深度研究立项流：把“值得看”推进到“是否可入池”
  • 周度组合审查流：检查组合排序、风格漂移、核心仓变化
P2 第三阶段再做
  • 月度风控与归因流：收益归因、风险归因、失败复盘、风险预算调整
L3

Agent 团队层

按买方职责拆角色，而不是按技术能力拆角色。

CIO / Supervisor

接收任务、调度团队、统一冲突观点、输出唯一正式结论。

Macro & Policy

跟踪宏观、政策、流动性，给出进攻 / 中性 / 防守市场态度。

Sector Analyst

先读行业知识库，再做增量分析，判断景气、政策、竞争与估值环境是否变化。

Company Analyst

围绕单个持仓或候选股判断 thesis 是否强化或弱化，给出操作倾向。

Bear Case

专门挑战多头逻辑，找忽略风险，定义何时认错。

Risk Officer

检查单票、行业、风格、流动性与事件风险，担任组合风险闸门。

Portfolio Manager

做候选与持仓之间的替代排序，解决“资金从哪儿出，去哪里”。

Monitoring & Memory

加载状态、写回状态、维护 thesis、观察项与历史结论。

Industry Knowledge Curator

维护行业知识库，对新信息去重、归类、版本化，决定哪些进入核心知识层。

L4

知识与记忆层

把行业判断和公司 thesis 变成可复用、可更新、可验证的长期资产。

行业知识库层

共享长期记忆
1. 行业静态底盘

行业定义、产业链地图、商业模式、竞争因子、估值框架、监管框架、术语。

2. 核心跟踪框架

关键指标、领先与滞后指标、真信号与噪音的判别规则。

3. 行业时序事实层

政策时间线、景气拐点、龙头事件、供需变化、价格利润摘要、争议演化。

4. 可复用观点层

历史观点、争论点、被验证与被证伪判断、常见误判模式。

公司 Thesis 记忆层

逐票维护
  • 核心投资逻辑
  • 关键驱动因素
  • 失效条件
  • 最近更新时间
  • 当前状态
  • 已验证 / 被证伪点

组合记忆层

组合级状态
  • 当前持仓与权重
  • 候选池
  • 历史调仓记录
  • 组合暴露
  • 观察事项

行业分析嵌入方式

先读存量，再看增量
  • 先读取：行业底盘、跟踪框架、当前行业状态卡、历史关键争议和判断
  • 再读取：最近 7 / 30 / 90 天变化、近期行业事件、持仓相关变化
  • 最后输出：今天发生了什么、是否改变原有判断、是否影响持仓和候选池
L5

状态管理层

支撑所有工作流持续运行的核心状态表与中间对象。

Position

ticker · name · weight · cost_basis · holding_days · sector · thesis_id

Thesis

thesis_id · ticker · core_claim · key_drivers · invalidation_conditions · last_updated · status

Position Update Card

ticker · thesis_status · today_view · suggested_weight_change · confidence · why_now · risk_flags

Action Item

ticker · action · weight_change · priority · reason · cancel_condition

下一步补充

候选池状态 · 行业状态卡 · 风险状态表 · 观察事项表

L6

执行与治理层

确保系统可以安全落地，且高影响动作不会绕过人工。

落地原则

  • v1 不自动下单
  • 所有实际交易动作由人批准
  • 风险和高影响动作必须强制人工介入

人工介入点

  • 系统异常：数据缺失、状态损坏、持仓与账户不一致
  • thesis 失效：核心逻辑被打穿、财务或治理风险爆发
  • 大幅操作：大幅加减仓、清仓、超常规新建仓
  • 低置信度高影响建议：建议动作大，但置信度偏低

核心主流程

每日持仓决策流

主触发为每个交易日 07:45，08:55 可条件重跑，最终输出《今日持仓操作单》。

0

交易日与系统检查

判断是否交易日，以及系统是否处于可运行状态。

1

状态快照加载

Monitoring & Memory 加载持仓、候选池、风险预算、thesis 与未完成事项。

2

隔夜信息扫描

Macro、Sector、Monitoring 扫描宏观、政策、公告、行业变化并回查知识库。

3

持仓逐票重评

Company、Bear、Risk 联合重评 thesis 强弱、今日动作与风险变化，产出 position_update_card。

4

候选池替代评估

Portfolio、Sector、Company、Risk 联合判断若调仓，资金最该从哪儿出来、去哪里。

5

组合级风险闸门

Risk Officer 给出 pass / pass_with_limit / reject。

6

CIO 汇总与冲突消解

统一口径、解决冲突、形成最终动作框架。

7

生成今日操作单

输出必须动作、可选动作、继续持有、风险提示、今日不要做的事。

8

人工确认

人对操作单执行批准、修改、打回或暂缓。

9

执行结果写回

Monitoring & Memory 写回批准结果、执行情况与后续观察项。

基础规则

当前已确定的投资与动作约束

仓位规则

  • 单票初始仓位：1% - 3%
  • 单票常规上限：5%
  • 核心高确信仓上限：8%
  • 单行业上限：25%

动作规则

  • thesis weakened + risk high → 优先减仓或退出
  • thesis unchanged + no new catalyst → 默认持有
  • thesis strengthened + valuation okay + risk pass → 可加仓
  • candidate clearly better than existing → 允许调仓替换

置信度规则

  • ≥ 0.75：允许给明确动作
  • 0.55 - 0.75：允许给条件性动作
  • < 0.55：只能给观察建议或人工复核
